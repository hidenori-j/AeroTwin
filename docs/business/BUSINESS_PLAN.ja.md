## 1. エグゼクティブサマリ

### 何を提供するのか

AeroTwinは、**自律移動ロボット**と**Unityによる3Dデジタルツイン**を組み合わせ、目に見えない室内空気環境（CO2滞留・温度ムラ・熱だまり）を立体的に可視化するBtoBソリューションです。

ロボットが実際の空間を走行しながら空気データと位置座標を収集し、PCのUnity上でその部屋の3Dモデルに「色のモヤ（ヒートマップ）」として描画します。数値の羅列ではなく、**誰が見ても一目でわかる"空気の映像"**を提供することが最大の価値です。

### 誰に提供するのか（初期ターゲット）

- **データセンター**：サーバーラックの熱だまりを特定し、冷却コスト削減に貢献する
- **大規模オフィス・工場**：換気改善の可否を客観的に証明し、設備投資稟議を通す根拠にする
- **植物工場**：環境ムラが収量・品質に与える影響を可視化し、生産効率を高める

### なぜ今なのか

- 2020年以降、CO2濃度と換気状況への関心が企業の設備担当者レベルまで広がった
- ROS 2・LiDAR・Unityの組み合わせが、中小チームでも扱えるコストと成熟度に達した
- 3Dプリンティング技術の普及により、専用外装・センサー隔離機構を低コストで実現できる

### 差別化の4軸

| 軸 | AeroTwinの強み |
|----|----------------|
| 見える化 | Unity上に「色のモヤ」として空気を描画。稟議書に貼れる直感的な映像を提供 |
| データ信頼性 | 3Dプリントの専用隔離チャンバーと導風ダクトでラズパイの排熱からセンサーを物理的に守る |
| プロ外観 | 自社ロゴ入りマット外装。「学生の工作」ではなく「産業機器」と認識させる |
| 短納期カスタム | 3Dプリンターで防塵カバー等を現場仕様に素早く設計変更できる |

## 2. 課題と市場機会

### 2.1 解決する課題

**空気環境は"見えない"から対処が遅れる。**

現在、企業の多くは固定式の温度・CO2センサーを数点設置しているか、あるいは計測機器そのものを持っていない。固定センサーでは、空間全体の「どこが問題なのか」「改善前後で何が変わったのか」を証明できない。その結果、以下の問題が生じている。

| 業種 | 具体的な課題 |
|------|-------------|
| データセンター | サーバーラック後方の熱だまりを特定できず、冷却を過剰設計。電力コストが膨らむ |
| 大規模オフィス | CO2が1,000ppmを超える「滞留ゾーン」が存在するが、特定・証明手段がない |
| 工場 | 作業エリアの温度ムラが品質・作業者の集中力に影響するが、見える化されていない |
| 植物工場 | CO2濃度・温度・湿度のムラが収量差に直結するが、マップで把握できていない |

### 2.2 市場の優先順位（初期仮説）

**第一優先：データセンター**

熱管理は直接的なコスト削減に繋がるため、ROIが明確で意思決定が速い。また計測結果を「冷却効率改善レポート」として納品できれば、次回診断や設備改修コンサルへの継続受注につながりやすい。

**第二優先：大規模オフィス（1,000名以上）・工場**

CO2測定・換気証明の需要は労働安全衛生法改正の文脈でも高まっており、設備担当者・総務部長が予算を持ちやすい。

**第三優先：植物工場**

技術への理解度が高く、実証実験として受け入れやすい。ただし予算規模が小さいため、当初は無料PoC先として活用し実績を積む位置づけとする。

### 2.3 なぜ今参入できるか

- LiDARの民生品価格が5万円以下に下落し、スタートアップが調達可能になった（2023〜2025年）
- ROS 2 Humble/Iron の安定版がリリースされ、SLAMのセットアップ工数が大幅減少した
- UnityのROS-TCP-Connectorにより、ROS 2とUnityのリアルタイム連携が公式に整備された

## 3. ソリューション詳細

### 3.1 サービスの流れ（Phase 1 スポット診断）

```
① 現場訪問・事前ヒアリング（半日）
    ↓  問題ゾーン・走行ルートの確認
② ロボット走行・データ収集（2〜4時間）
    ↓  SLAMで地図生成 + SCD41でCO2/温度/湿度をリアルタイム記録
③ Unityで3Dヒートマップを構築（当日〜数日後）
    ↓  実際の間取りに重ねた「空気環境3Dモデル」を生成
④ レポート納品・改善提案（オンライン/訪問）
    ↓  「どこが問題で、なぜ問題で、どう直すか」を映像で説明
```

### 3.2 ロボットによる空間環境スキャン

RPLiDAR S3が360度レーザースキャンで空間の形状を認識し、ROS 2のSLAM（Simultaneous Localization and Mapping）アルゴリズムが「地図上の自分の位置座標」をリアルタイムで計算します。同時にSCD41センサーがCO2濃度・温度・相対湿度を計測し、各測定点のXY座標と紐づけてUDP経由でPCに送信します。

Phase 1では**PS4コントローラーによる手動操縦**を採用。自律走行の開発コストを省き、「確実にデータが取れる」ことを最優先します。

### 3.3 Unity 3Dヒートマップによる可視化

PCのUnityアプリがロボットから受信したデータをもとに、次の3つを組み合わせた映像を生成します。

- **実際の部屋の3Dモデル**（ロボットが生成したLiDARマップをベースに構築）
- **空気データの色付きモヤ**（CO2高=赤、適正=緑などのグラデーション表現）
- **時系列再生**（走行ルートに沿って空気データが変化する様子をアニメーション表示）

顧客の設備担当者・経営層が**「ここが問題だ」と直感的に理解できる映像**を作ることで、コンサルティング価値と稟議書への転用価値を同時に提供します。

### 3.4 3Dプリントによる排熱隔離の技術的価値

Raspberry Pi 5は高負荷時に約5〜8Wの熱を発生させます。この熱が直接SCD41センサーに届くと、気温計測値が実際より2〜5°C高くなり、CO2計測値にも影響します。これはセンサーを「正しい場所に置いても正しくない値が出る」という根本的な問題です。

AeroTwinでは3Dプリントで設計した**専用の隔離チャンバーと導風ダクト**でこれを解決します。

```
[ラズパイ排熱ゾーン]  ←壁で物理的に隔離→  [センサーチャンバー]
                                              ↑
                                       外気を引き込む専用ダクト
                                       （走行風を利用）
```

これにより「物理的に担保された測定精度」を実現し、顧客に対して技術的な説得力を持って精度保証できます。

## 4. 製品・技術アーキテクチャ

### 4.1 ハードウェア構成

| 役割 | 選定部品 | 採用理由 |
|------|----------|----------|
| 足回り（下半身） | ROS対応スマートカーキット（アルミフレーム・エンコーダ付き） | 力のかかる下半身は自作せず、LiDARに必須な「滑らかな低速走行」を既製品で確実に実現 |
| 頭脳（計算） | Raspberry Pi 5（8GB） | SLAM計算（NavSat2/Cartographer相当）を遅延なく処理できる最新の処理能力 |
| 目（空間認識） | RPLiDAR S3（またはS2） | 太陽光・黒い壁への耐性が高く、高速スキャンで座標ロストを防ぐ業務用グレード |
| 鼻（空気計測） | SCD41センサーモジュール | スイス製Sensirion社NDIR方式。CO2・温度・湿度を1チップで計測、I2C接続 |
| 外装・機構（上半身） | 3Dプリンター（PETG素材）+ Fusion 360設計 | 排熱隔離ダクト・外装カウル・LiDARマウントを一体設計で自社専用化 |
| 電源 | モバイルバッテリー（大容量）| ケーブルなし走行を実現。連続稼働2〜4時間を確保 |
| 通信 | Wi-Fi（UDP） | ROS 2トピックをPCへリアルタイム送信 |
| 操縦 | PS4コントローラー（Bluetooth） | Phase 1の手動操縦。直感的操作で現場スタッフでも扱える |

### 4.2 ソフトウェアスタック

```
[Raspberry Pi 5 側]
  Ubuntu 22.04 LTS
  └─ ROS 2 Humble
       ├─ slam_toolbox          … LiDARデータから地図と自己位置を同時推定
       ├─ rplidar_ros2          … RPLiDARドライバ
       ├─ teleop_twist_joy      … PS4コントローラー入力をcmd_velに変換
       ├─ sensor_publisher.py  … SCD41からI2Cでデータ取得し、ROS 2トピックへ
       └─ udp_bridge.py        … 座標+センサーデータをUDPでPC側へ転送

[PC側 Unity]
  Unity 2022 LTS
  └─ ROS-TCP-Connector（またはカスタムUDP受信スクリプト）
       ├─ MapBuilder.cs        … LiDARスキャンから3D空間モデルを構築
       ├─ HeatmapRenderer.cs  … 座標×センサー値をボリュームヒートマップとして描画
       └─ TimelinePlayer.cs   … 走行ログを時系列で再生
```

### 4.3 データフロー

```
SCD41センサー
    ↓ I2C
Raspberry Pi 5
    ↓ ROS 2トピック (/sensor_data, /map, /odom)
    ↓ UDP（Wi-Fi LAN）
Unity (PC)
    ↓ 3Dヒートマップ描画
    ↓ 動画キャプチャ / PDF出力
顧客へのレポート納品
```

### 4.4 段階的な自律化設計

| フェーズ | 操縦方式 | 必要開発 |
|--------|---------|---------|
| MVP（Phase 1） | PS4手動操縦 | 既存 teleop_twist_joy で即時対応可能 |
| Phase 2 | 半自律（経路指定→自動走行） | Nav2 スタック導入、コストマップ調整 |
| Phase 3 | 完全自律（スケジュール巡回） | 自動ドッキング充電、エレベーター連携検討 |

## 6. 競争優位性

### 6.1 競合カテゴリの整理

| 競合カテゴリ | 代表例 | AeroTwinとの差分 |
|-------------|--------|----------------|
| 固定式IoTセンサー | SwitchBot CO2センサー、Netatmo | 一点計測。「どこが悪いか」のマップが作れない |
| 固定センサー網の大量設置 | ビルオートメーション会社 | 設置・配線コストが高額。リノベーション時しか対応できない |
| 一般的なロボットSI | 大手SIer、ロボットメーカー | 導入コスト数千万円〜。中小・中堅企業には手が出ない |
| 調査会社による手動計測 | 環境コンサル各社 | 人が歩いてポイント計測。解像度が粗く、3D可視化なし |

### 6.2 競争優位性の4軸詳細

**軸①：圧倒的な見える化**

競合他社が「数値の表」を出す中、AeroTwinは「色のモヤが漂う3D映像」を出します。企業の設備投資稟議では「経営層が直感的に理解できる資料」があるかどうかで承認速度が変わります。このビジュアルギャップが最初の差別化です。

**軸②：物理的に担保されたデータ信頼性**

3Dプリントの隔離チャンバーは、単なる「見た目の工夫」ではなく、センサー精度への技術的な投資です。「なぜこのロボットのデータが信頼できるのか」を顧客に説明できる構造的な根拠になります。

**軸③：プロフェッショナルな外観によるブランディング**

機材がむき出しでは、企業担当者は「これはパーツの集まり」と認識し、価格交渉で値踏みされます。自社ロゴ入りのマット質感の専用カウルに覆われたロボットは、「このメーカーの製品」として知覚されます。これは心理的な価格上限を引き上げる効果があります。

**軸④：3Dプリントによる迅速なカスタム対応**

競合他社が「既製品の組み合わせで対応」する中、AeroTwinは現場仕様の防塵カバー・特殊マウントを数日で設計・出力できます。これは「この現場専用の機材を作ってもらえた」という顧客体験を生み出し、ロックイン効果を高めます。

| 予算感 | 単発30〜50万円の調査費用を承認できる |

### 9.2 営業チャネルと施策

**チャネル①：SNS / 動画マーケティング**

- PR動画（1分）をLinkedIn、X（Twitter）、YouTube Shortsに同時投稿
- 「CO2可視化」「デジタルツイン」「データセンター冷却」等のキーワードで設備担当者層にリーチ
- 月次でビフォー・アフター動画や技術解説記事を追加投稿

**チャネル②：無料テスト → 口コミ紹介**

- 知人・友人のオフィス・倉庫・工場で無料スキャンを2〜3件実施
- レポートを納品し「これをSNSでシェアしてよい」と許可をもらう
- 担当者からの紹介営業を最初の有償案件へのルートとする

**チャネル③：展示会・勉強会への出展**

- 製造業向け展示会（メカトロテック、スマートファクトリーJapan等）への参加検討
- ロボット系・DX系の勉強会でデモを行い、設備担当者へのアクセスを得る

**チャネル④：直接アプローチ（ターゲットリスト型営業）**

- データセンター運営会社・工場管理会社のWebサイトから担当者情報を収集
- LinkedInで設備管理者・施設管理者に直接メッセージ
- メール文面は「御社の設備コスト削減に繋がるデータをお見せできます」という具体的なオファー型にする

## 10. リスクと対策

| リスク | 影響度 | 可能性 | 対策 |
|--------|--------|--------|------|
| 測定精度への疑義 | 高 | 中 | 3Dプリント隔離チャンバーの設計根拠を文書化。参照センサー（固定設置のSCD41）との比較データを用意 |
| 走行中の座標ロスト | 高 | 中 | RPLiDAR S3の高精度スキャン設定を最適化。走行前にルート確認と環境チェックを徹底 |
| 現場の床状況による走行不能 | 中 | 中 | 事前ヒアリングで走行困難エリアを特定。カーペット・段差への対応を車体キットで確認 |
| 顧客の価格抵抗 | 高 | 中 | 無料テストで「このレポートが30〜50万円の価値あり」を先に体験させてから有償化 |
| 競合による模倣 | 中 | 低 | 3Dプリント外装・導風ダクトの設計ノウハウを蓄積し、カスタマイズ速度で差をつける |
| バッテリー切れによるスキャン中断 | 中 | 低 | 大容量モバイルバッテリーを選定。現場では予備バッテリーを持参 |
| 技術者不足による対応キャパ不足 | 高 | 中（将来） | Phase 2以降は協業エンジニアや外部パートナーとの体制構築を早期に検討 |
| Wi-Fi環境の劣悪な現場 | 低 | 中 | UDP遅延が増えてもデータ欠損を防ぐバッファ処理を実装。極端な場合はデータをオンボード保存して後処理 |

## 付録：用語集

| 用語 | 説明 |
|------|------|
| ROS 2（Robot Operating System 2） | ロボット開発向けのオープンソースミドルウェア。センサーデータの処理・通信・制御を標準化する |
| SLAM（Simultaneous Localization and Mapping） | ロボットが自分の位置を推定しながら同時に地図を作るアルゴリズム |
| LiDAR（Light Detection and Ranging） | レーザー光を照射し、反射するまでの時間で距離を測定するセンサー |
| SCD41 | スイスSensirion社製のCO2・温度・湿度複合センサー。NDIR（非分散型赤外線）方式 |
| NDIR（Non-Dispersive Infrared） | CO2分子が特定波長の赤外線を吸収する性質を利用した高精度計測方式 |
| デジタルツイン | 現実の物体・空間をデジタル上に複製したモデル。センサーデータでリアルタイム更新される |
| PETG（Polyethylene Terephthalate Glycol） | 3Dプリント素材の一種。耐熱性・強度・耐薬品性に優れ、産業用途に適する |
| Nav2 | ROS 2の自律ナビゲーションスタック。地図上でのルート計画・障害物回避を担う |
| UDP（User Datagram Protocol） | 低遅延のデータ送信プロトコル。リアルタイム性を重視する用途に使用 |
