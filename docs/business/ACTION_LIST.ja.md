# AeroTwin 詳細アクションリスト

**対象期間：初期3ヶ月**
**目的：MVP完成、営業デモ作成、初回有償受注の獲得**

---

## 使い方

このドキュメントは、AeroTwinの事業計画を実行タスクへ分解したチェックリストです。

- 毎週の終わりに完了項目を確認する
- 完了できなかった項目は、理由を「技術」「調達」「時間」「営業」のどれかに分類する
- 判断に迷った場合は「初回受注に近づくか」を優先基準にする
- 最初の3ヶ月は完全自律化よりも、手動操縦で確実にデータ取得と可視化ができることを優先する

## 1. Week 1：ロボット基盤とROS 2環境

### 1.1 車体組み立て

- [ ] スマートカーキットの内容物を確認する
- [ ] フレーム、タイヤ、モーターを組み立てる
- [ ] モータードライバを固定する
- [ ] Raspberry Pi 5を仮固定する
- [ ] バッテリー位置を仮決めする
- [ ] 配線がタイヤやLiDARに干渉しないように仮整理する
- [ ] 重心が大きく偏っていないか確認する

### 1.2 Raspberry Pi 5の初期設定

- [ ] Ubuntu 22.04 LTSをインストールする
- [ ] SSH接続を有効化する
- [ ] Wi-Fi接続を設定する
- [ ] 固定IPまたは接続先の確認方法を決める
- [ ] ROS 2 Humbleをインストールする
- [ ] `colcon`、`rosdep`、開発用ツールを導入する
- [ ] 起動時に必要な環境変数を設定する

### 1.3 手動操縦の確認

- [ ] PS4コントローラーをRaspberry Pi 5へ接続する
- [ ] `teleop_twist_joy` を導入する
- [ ] コントローラー入力がROS 2トピックに出ることを確認する
- [ ] モーター制御ノードへ `cmd_vel` を渡す
- [ ] 前進、後退、左旋回、右旋回を確認する
- [ ] 低速走行時のガタつきを確認する
- [ ] 急停止時に転倒しないか確認する

### 1.4 電源・発熱の確認

- [ ] バッテリー駆動で30分以上走行させる
- [ ] Raspberry Pi 5の温度を記録する
- [ ] モータードライバの発熱を確認する
- [ ] バッテリー残量の減り方を確認する
- [ ] 配線の抜けやすい箇所を特定する

**完了条件：PS4コントローラーでロボットを安定して走行できる。**

## 2. Week 2：LiDAR・SLAM・空気センサー

### 2.1 RPLiDARの動作確認

- [ ] RPLiDARをロボット上部に仮固定する
- [ ] LiDARが水平になるように調整する
- [ ] ケーブルが回転部に干渉しないことを確認する
- [ ] RPLiDAR用ROS 2ドライバを導入する
- [ ] `rviz2` でレーザースキャンを表示する
- [ ] 壁、机、椅子などの障害物が正しく見えるか確認する

### 2.2 SLAMの確認

- [ ] `slam_toolbox` を導入する
- [ ] 1部屋を低速で走行して地図を生成する
- [ ] 生成地図に大きな歪みがないか確認する
- [ ] 同じ場所に戻ったときに自己位置が大きくズレないか確認する
- [ ] 走行速度を変えて地図精度を比較する
- [ ] 座標ロストが起きやすい場所を記録する

### 2.3 SCD41の動作確認

- [ ] SCD41をI2CでRaspberry Pi 5へ接続する
- [ ] I2Cアドレスを確認する
- [ ] CO2、温度、湿度を読み取るPythonスクリプトを作成する
- [ ] 1秒ごとに値を取得する
- [ ] 固定状態で10分間ログを取る
- [ ] 人の呼気などでCO2値が変化することを確認する
- [ ] Raspberry Pi 5の排熱が温度値に影響しないか仮確認する

### 2.4 ROS 2トピック化

- [ ] SCD41の値をROS 2トピックとして配信する
- [ ] トピック名を決める（例：`/air_quality`）
- [ ] タイムスタンプを付与する
- [ ] `ros2 topic echo` で値を確認する
- [ ] `/odom` または自己位置情報と同時に取得できることを確認する

**完了条件：地図、自己位置、CO2、温度、湿度を同時に取得できる。**

## 3. Week 3：Unity連携と最小ヒートマップ

### 3.1 送信データ形式の決定

- [ ] 送信する項目を決める（時刻、x座標、y座標、CO2、温度、湿度）
- [ ] JSONまたはCSV風文字列のどちらで送るか決める
- [ ] 欠損値の扱いを決める
- [ ] 送信間隔を決める（例：1秒ごと）
- [ ] ロボット側にもログを保存するか決める

### 3.2 UDPブリッジの実装

- [ ] Raspberry Pi 5側で座標とセンサー値を結合する
- [ ] UDPでPCへ送信する
- [ ] PC側で受信ログを確認する
- [ ] 受信できない場合のネットワーク確認手順をメモする
- [ ] データ欠損時にログへ警告を出す

### 3.3 Unity最小実装

- [ ] Unity 2022 LTSでプロジェクトを作成する
- [ ] UDP受信スクリプトを作成する
- [ ] 受信した座標に点を描画する
- [ ] CO2濃度に応じて色を変える
- [ ] 温度に応じた表示へ切り替えられるようにする
- [ ] 点群を時間経過で蓄積する
- [ ] 走行ログを再生できる簡易機能を作る

### 3.4 デモとして見える状態にする

- [ ] 背景に簡易的な部屋の枠を表示する
- [ ] 現在位置のロボットアイコンを表示する
- [ ] CO2値の凡例を表示する
- [ ] 画面録画を行う
- [ ] 説明なしでも「空気が可視化されている」と伝わるか確認する

**完了条件：実際の走行に合わせて、Unity上に空気データの色付き点群が表示される。**

## 8. 意思決定基準

### 優先すること

- 手動操縦でも確実にデータが取れること
- Unity画面で価値が一目で伝わること
- 顧客が稟議に使える資料になること
- 現場で説明しやすい外観とストーリーがあること
- 初回受注に近づく作業であること

### 後回しにすること

- 完全自律走行
- 自動充電
- 複数台連携
- 高度なSaaS管理画面
- 完璧な3D空間再構築
- 過度な量産設計
